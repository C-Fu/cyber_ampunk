# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (binds every section below):** The frozen visual identity from Phases 1–2 (`.planning/phases/01-i18n-foundation/01-UI-SPEC.md` + `.planning/phases/02-language-toggle-kl-intro-story/02-UI-SPEC.md`, both **approved**) carries forward verbatim — type ramp, `--cyber-*` tokens, chrome geometry, copy rules C-1…C-4 / T-1…T-7 / E-1…E-5, and the Phase 2 story presentation (S-1…S-5, ST rules, 100s scroll). This phase does **not** redesign the story typography; the highlight is a *state style applied to the existing `.intro-story-line` ramp*, not a new text style. This contract covers only the FOUR NEW design surfaces Phase 3 introduces (per 03-CONTEXT.md D-01…D-05 LOCKED):

1. **Per-line narration highlight** — the currently-spoken `.intro-story-line` (D-03, TTS-05).
2. **Replay button** — restarts narration, in the intro button row (TTS-06, D-05).
3. **Narration-source label** — tiny, unobtrusive, names the active source (TTS-04).
4. **Mute-integration visual behavior** — the existing audio button governs; narration shows no separate mute control (TTS-03, D-05).

Where this spec restates a locked decision from `03-CONTEXT.md`, the source is cited and NOT reopened. Autonomous run: agent-decided items are marked **[agent-decided]**.

**Structural prerequisite (flag for planner):** the current overlay self-removes on ENTER (`playExit` → `root.remove()` in `src/ui/intro/createIntroOverlay.js`), but TTS-05/TTS-06 require the story region, replay button, and source label to remain on screen for the whole ~3–5 min narration. The planner must adjust the intro flow so the overlay persists during narration (e.g. story window + replay row persist while narration plays, per D-02 full-story delivery). This contract specifies the visuals of those persistent elements; the persistence mechanism is a planning decision.

## Typography

**No typeface, size, weight, or line-height changes.** The story keeps the exact Phase 2 ramp; new elements use the recorded scale:

| Role | Size | Weight | Line Height | Element |
|------|------|--------|-------------|---------|
| Story line (unchanged) | `clamp(0.78rem, 1.7vw, 0.95rem)`, `letter-spacing: 0.01em` | **400** (highlight does NOT change weight — see H-1) | 1.45 | `.intro-story-line` — existing ramp verbatim |
| Label | `0.62rem`–`0.68rem`, `letter-spacing: 0.22em`, uppercase | 500 | 1 | Source label ("SUARA: AUDIO" style) — matches the 9px/0.22em chrome label family, one step smaller because it sits inside the cinematic overlay **[agent-decided]** |
| Button label | `clamp(0.8rem, 1.4vw, 0.95rem)`, `letter-spacing: 0.28em` | 500 | 1 | Replay button (if text-labeled) — matches `.intro-button` |

Typography rules for this phase (binding):

- **H-1 — Highlight is color + glow, never geometry.** The active line changes ONLY `color`, `text-shadow`, and (optionally) `opacity` of neighbors. No font-weight change (Orbitron weight changes shift glyph widths and would jiggle the centered column), no size change, no letter-spacing change, no padding/margin change. Highlight is a paint change, not a layout change. **[agent-decided — zero-reflow requirement]**
- **H-2 — No reflow on state swaps:** source-label text changes (asset → fallback) and highlight hand-offs (line N → N+1) must land in a single painted frame with no shift of the story window, actions row, or credit. Text for both source states is length-budgeted ≤ 22 chars (see copy table) so the swap is width-safe within the label's centered box. **[agent-decided]**
- **T-8 — Story line spans:** each `.intro-story-line` is already its own `<p>` (per `createIntroOverlay.js` renderStory) — this is exactly the highlight target structure Phase 2's key design anticipated. Highlight = toggling a `is-speaking` class (or equivalent attribute) on that `<p>`; no new span nesting inside lines, no textContent rewrite during playback (language parity rules T-2-03/D-04 still govern). **[agent-decided]**

## Color

**No color-token changes.** `--cyber-*` variables (`src/ui/core/global.css`) are untouched. New states consume them:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | scene render + overlay glass | unchanged |
| Secondary (30%) | `rgba(255, 255, 255, 0.9)` story text / `rgba(8, 10, 16, 0.28)` button glass / `var(--cyber-border)` | Story lines idle, replay button idle, source label idle |
| Accent (10%) | cyan `var(--cyber-text)` `rgba(34, 211, 238, 0.92)` + glow `0 0 18px rgba(34, 211, 238, 0.25)`-family | **exclusively**: (a) the currently-spoken story line, (b) the replay button's hover/active state — and nothing else |
| Destructive | none | no destructive actions added |

Accent reserved for: the pre-existing accent carriers (unchanged — toggle active segment, settings titles, toast action) **plus the spoken-line highlight and replay-button hover** — and nothing else. The source label is deliberately NOT accent at idle: it is a status readout, muted; it MAY take `var(--cyber-text)` only in its fallback/error state (see SL-3) **[agent-decided]**.

- **H-3 — Active line (highlight contract, D-03):** the spoken line renders `color: var(--cyber-text)` (cyan), `text-shadow: 0 2px 18px rgba(0, 0, 0, 0.5), 0 0 14px rgba(34, 211, 238, 0.35)` (the existing dark shadow PLUS a cyan bloom), and `opacity: 1`. Non-spoken lines dim slightly: `color: rgba(255, 255, 255, 0.55)` (down from 0.9), so the spoken line reads without the highlight being a "redesign" of the ramp. Transition `color 0.3s ease, opacity 0.3s ease, text-shadow 0.3s ease` on `.intro-story-line` — hand-offs cross-fade in 300ms, no flicker. **[agent-decided — pattern-matched to the active-preset accent treatment from TG-3]**
- **H-4 — Highlight window-vs-scroll independence:** the highlight applies to the line element regardless of scroll position. Because the scroll is a CSS transform animation and the highlight is paint-only, the two compose without interaction — the spoken line glows even when partially faded by the mask at the window edges (acceptable: the mask is 12% feather, most of the spoken line is fully visible for the bulk of its audio). The planner MAY couple scroll timing to the cue table (carried decision: scroll duration tuned to audio length) — visually the highlight leads, the scroll follows. **[agent-decided]**
- **R-1 — Replay button states:** idle = `.intro-button` glass family shrunk to icon-button size (`background: rgba(8, 10, 16, 0.28)`, `border: 1px solid rgba(255, 255, 255, 0.88)`, `border-radius: 999px`, backdrop blur 10px — copied verbatim from `.intro-button` so the row reads as one family). Hover = `.intro-button:hover` trio translated to icon scale (`background: rgba(255, 255, 255, 0.12)`, border `#ffffff`, cyan glow `0 0 18px rgba(34, 211, 238, 0.25)`, `translateY(-2px)`). Active-press = `translateY(0)`. While narration is playing the button shows its normal idle state (it is an affordance, not a toggle — pressing restarts). While narration is NOT playing (muted, finished, or fallback-failed before start), the button is `disabled` at `opacity: 0.4` — it never looks broken, only quiet. **[agent-decided]**

### Mute-integration copy/state contract (TTS-03, D-05)

- **MU-1 — No new mute UI.** The existing audio button (`createAudioButton.js`, `audioState` pub/sub) is the sole mute control. Narration adds no button, no badge, no second volume surface. **[locked by D-05/carried decision — not reopened]**
- **MU-2 — Mute visual behavior:** when `audioState` flips to muted during narration, the spoken-line highlight fades out over the same 300ms transition (H-3) and the source label dims to `opacity: 0.4` (same quiet state as a disabled replay). On unmute mid-story, narration behavior (resume vs stay-cancelled) is a planning decision per carried rules ("mute kills narration immediately"); this spec covers only the visuals: label dim ↔ active, highlight present ↔ absent, always in the same frame as the audio button's own icon swap. **[agent-decided]**
- **MU-3 — Replay on mute:** replay while muted must not start audio; the button is `disabled` while muted (MU-2 quiet state). **[agent-decided — prevents a dead affordance]**

## Component Contracts (the four new surfaces)

### HL — Per-line highlight (D-03, TTS-05)

- **HL-1 — Target elements:** the 49 `.intro-story-line` `<p>` elements rendered by `renderStory()` in `src/ui/intro/createIntroOverlay.js`, keyed `intro.story.l01…l49` (Phase 2 D-06 single source of truth — the SAME keys drive the audio cue table). Highlight hand-off = remove class from line N, add to line N+1, driven by per-line audio chunk ended/current-time events (mechanism = planner's per D-02 asset-format discretion). **[agent-decided]**
- **HL-2 — Only one line highlighted at a time.** Exactly zero-or-one active line at any instant: zero before narration starts, during mute (MU-2), after the last line ends, and on fallback-failure. Never two overlapping. **[agent-decided]**
- **HL-3 — End of story:** when the final line completes, the highlight clears (all lines return to the dimmed idle state) and stays cleared until replay. No "replay me" pulse, no blinking affordance — the replay button itself is the invitation (R-1 hover glow). **[agent-decided]**
- **HL-4 — Language switch during playback:** `renderStory()` rebuilds the line elements on `syncText`; the narration module must re-query/rebind highlight targets after any story rebuild (or the highlight silently dead-ends — plan must verify this path). Visual contract: highlight state survives the rebuild (same spoken index re-applied instantly, no flash of all-dim). **[agent-decided — flagged as a planner verification item]**
- **HL-5 — Reduced motion:** the 300ms color/opacity transitions are opacity/color-only already (no transform) — safe under `prefers-reduced-motion` without extra work. No additional keyframes introduced by the highlight. **[agent-decided]**

### RP — Replay button (TTS-06, D-05)

- **RP-1 — Placement:** in the existing `.intro-actions` row, as a sibling AFTER the ENTER button (ENTER remains the primary, leftmost-first reading order in a centered row; replay is secondary) **[agent-decided]**. If the planner's intro-flow change retires ENTER after the first click, replay may take its visual slot — the contract is: replay lives in the actions row at ENTER's scale family (44px round), never floating over the story window, never in the header (it is intro-scoped, not chrome). **[agent-decided]**
- **RP-2 — Icon:** Phosphor arrow-counterclockwise glyph (arrow-clockwise family in `phosphorIcons.js`), 18px, `aria-hidden`, with the button carrying `aria-label` from the copy table. `aria-label` re-syncs via `syncText` on language change (data-i18n-aria pattern from Phase 1's walker). **[agent-decided]**
- **RP-3 — Keyboard:** native `<button>`; `:focus-visible { outline: 2px solid rgba(255, 255, 255, 0.35); outline-offset: 2px }` copied verbatim from the TG-4 treatment. Enter/Space activate. **[agent-decided]**
- **RP-4 — Behavior:** click restarts narration from line 1 (per carried decision D-05 TTS-06 unchanged); the highlight resets to line 1 in the same frame; the story scroll restarts from the top (the existing `restartStoryScroll()` mechanism — replay reuses it verbatim). Disabled states per R-1/MU-3. **[agent-decided]**

### SL — Narration-source label (TTS-04)

- **SL-1 — Shape:** single centered `<p>` under the story window (`margin-top: 0.5rem`), Orbitron, `0.62–0.68rem`, uppercase, `letter-spacing: 0.22em`, idle color `rgba(255, 255, 255, 0.45)` — present but quiet. It reads as a whisper of metadata, not chrome. **[agent-decided]**
- **SL-2 — Content:** exactly one of the three copy-table states, set from the narration module's actual source state (asset / fallback-TTS / unavailable). Never shows the voice NAME (e.g. "OsmanNeural") — device-specific names are noise; the three-state enum is the whole contract. **[agent-decided]**
- **SL-3 — Fallback/error state:** when the graded chain bottoms out at text-only (or asset + TTS both unavailable), the label switches to the unavailable copy AND takes `color: var(--cyber-text)` at `opacity: 0.6` — the one moment the label is allowed cyan, because the user is now in a genuinely degraded experience worth noticing. No other state uses accent. **[agent-decided]**
- **SL-4 — Localization:** label text lives in the dictionaries (`intro.voice.*` keys suggested), re-synced via the overlay's existing `syncText` + the narration module's state subscription (two inputs: language, source-state; label re-derives from both). **[agent-decided]**

### MU — Mute integration (TTS-03) — covered by MU-1…MU-3 above; no new visual surfaces.
