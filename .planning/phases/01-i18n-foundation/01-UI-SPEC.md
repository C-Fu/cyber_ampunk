# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (binds every section below):** This phase changes **no visual design**. The existing
cyberpunk chrome (header, settings, about, intro overlay, walk hints, HUD, virtual joystick, walk
prompt, performance notice, loader overlay) stays pixel-identical. The contract below governs the
four surfaces localization actually touches: (1) text-length management under EN→MS expansion,
(2) typography of Latin-script BM in the existing fonts, (3) the BM copywriting contract, and
(4) language-swap rendering behavior (built dormant this phase, exercised in Phase 2). Where this
spec restates a locked decision from `01-CONTEXT.md` (D-01…D-10), the source is cited and the
decision is NOT reopened.

## Spacing Scale

**No spacing values change in this phase.** The existing chrome's spacing is untouched; this
section records the values that the text-expansion budget (below) must respect, so the executor
knows which boxes are elastic and which are fixed.

Existing chrome geometry relevant to BM text (from `src/ui/chrome/header.css`,
`src/ui/walk/hudPanel.css`, `src/ui/intro/introOverlay.css`):

| Element | Current constraint | Elasticity under BM |
|---------|--------------------|---------------------|
| Header action buttons (`ABOUT`/`SOURCE`) | `min-width: 44px; height: 44px; padding: 0 28px; font-size: 9px; letter-spacing: 0.22em` | Width is `auto` with `min-width` — grows freely; labels are `display: none` below 640px |
| Settings icon button | `44px × 44px` fixed (icon only) | Not text-bearing |
| HUD vitals row | `.hud-stats { max-width: 240px; overflow: hidden }`, labels 9px/8px | **Fixed budget — see expansion rule E-2** |
| HUD stat chips (ENERGY/SIGNAL) | `padding: 3px 8px 3px 6px`, 8px labels, value `margin-left: auto` | Flexible within `max-width: 240px` row |

| Intro tagline | `max-width: 22rem` (16.5rem ≤480px), `text-wrap: balance` | Wraps to multiple lines — length budget applies (copy rule C-4) |
| Walk prompt / move hint inner frames | Content-sized chips, `letter-spacing` per CSS | Grows freely within viewport |
| Loader status line | Single-line status text in `createLoaderOverlay` | Must stay single-line — see E-3 |
| Settings panel labels/sections | Content-stacked (`font-size: 16–22px` headings, `0.72rem` hints) | Panel scrolls; grows freely |

## Typography

**No typeface, size, weight, or line-height changes.** Recorded so the checker can verify BM text
renders under the existing type system:

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body (settings/about copy) | 0.72–1.0rem per existing CSS | 400–500 | existing | Orbitron (chrome) / Gloock (per existing rules) |
| Label / kicker / HUD | 7–10px (8–9px mobile) | 600 | 1 (chips) | Orbitron, `letter-spacing: 0.14–0.42em` |
| Heading (panel/section titles) | 16–22px | per existing CSS | existing | Orbitron |
| Display (intro brand / ENTER) | `clamp(2.6rem, 11vw, 5.75rem)` / `clamp(0.8rem, 1.4vw, 0.95rem)` | 600–700 / 500 | 0.86 / 1 | Orbitron |

Typography rules for BM copy (binding):

- **T-1 — Script coverage:** BM (Bahasa Melayu, `ms`) uses unaccented basic Latin letters only.
  Orbitron and Gloock Latin subsets already cover it — verified glyph subsets in
  `public/fonts/fonts.css` (`latin`, `latin-ext`). Zero font-file changes. (Agent-decided, from
  font-subset inspection.)
- **T-2 — Uppercase safety:** Chrome labels render via CSS `text-transform: uppercase`
  (`.app-header-about-btn`, `.hud-label`, `.intro-kicker`, `.intro-credit`). BM has no
  case-orthography conflicts (no `i`→`İ` dotting like Turkish). Store dictionary values in
  sentence case; let CSS transform. Exception: the intro brand lines
  (`THREEJS`/`PUNK` letter-split) are literal uppercase in the dictionary — the letter-split
  animation (`splitIntoLetters`) consumes `textContent` verbatim.
- **T-3 — Letter-spacing:** Wide tracking (0.22–0.42em) is applied to short labels only. Because
  tracking amplifies expansion (see E-1), BM labels must respect the per-element character
  budgets in the Copywriting Contract, not just pixel width.
- **T-4 — No `hyphens: auto`:** Unreliable for `ms` across browsers (research PITFALLS.md). Do
  not add it as an expansion mitigation. `text-wrap: balance` already on the intro tagline is the
  only wrap polish allowed.

## Copywriting Contract

Source of authority: D-09 (formal-clean BM labels, cyberpunk flavor reserved for the intro story
— Phase 2) and D-10 (AI drafts, owner reviews wording in the dictionary files). All BM copy below
is **draft-for-owner-review** per D-10 — the executor puts these drafts (or better) into
`src/i18n/dictionaries/bm.js`; final wording authority is the owner's.

### Tone contract (binding)

- **C-1 — Formal-clean BM** (D-09): standard register, no slang (`korop`, `gila`-intensifiers),
  no `-lah`/ke- prefix colloquialisms. Function words: `Tetapan` (settings), `Tentang` (about),
  `Kawalan` (controls), `Tutup` (close). Cyberpunk flavor lives only in loader statuses and
  (Phase 2) the intro story.
- **C-2 — Sentence case in dictionaries; CSS uppercases where the design already does.** (T-2.)
- **C-3 — Both dictionaries in parity** (LANG-03): every key below exists in `bm.js` AND `en.js`.
  EN side reproduces the current live English strings verbatim (they are the pre-localization
  baseline — no rewrites).
- **C-4 — Length budgets:** intro tagline ≤ ~48 chars EN / ~58 chars BM to stay ≤ 2 wrapped lines
  at `max-width: 22rem`; loader statuses ≤ ~26 chars BM to hold one line; HUD chip labels ≤ 8
  chars BM (see E-2).

### Text-length management (the core visual risk of this phase)

Research baseline: EN→MS expands **15–30%** (PITFALLS.md). Binding rules:

- **E-1 — Budget check at authoring time:** every BM string is authored against the length
  budgets in C-4, because tracking-heavy small caps (T-3) amplify visual width beyond raw
  character count.
- **E-2 — HUD fixed-width labels:** `.hud-stats` is capped at `max-width: 240px` with
  `overflow: hidden` and wide-tracking 8–9px labels. HUD BM labels are chosen ≤ 8 characters
  (`VITAL`, `TENAGA`, `ISYARAT`). If a label overflows in review, **shorten the copy first**
  (owner review, D-10); only if no acceptable short BM word exists, widen `max-width` in
  `hudPanel.css` by the minimum increment — never remove `overflow: hidden` and never scale font
  below the mobile minimum (7px).
- **E-3 — Single-line lockups:** loader status, header labels, intro button, walk-prompt title
  must not wrap. BM drafts are written to fit; no `white-space` changes.
- **E-4 — No layout redesign:** any CSS adjustment for expansion follows existing patterns and
  is a width bump on the specific selector only (CONTEXT agent's-discretion item 4). No grid,
  padding-scale, font-size, or breakpoint changes.
- **E-5 — Verification:** at 360px viewport width (mobile floor) and 1920px, every migrated
  surface renders BM with no clipping (except the pre-existing compact-HUD collapse), no wrap in
  single-line lockups, and no horizontal overflow of fixed chrome.

### Language-swap visual behavior (dormant path built this phase)

Contract for the `setLanguage` re-render, verified now via code shape and exercised in Phase 2:

- **L-1 — Instant, no reflow glitch:** a language change performs `textContent` /
  `setAttribute("content"|"aria-label")` writes only (D-03, ARCHITECTURE Anti-Pattern 4). No
  `innerHTML` dictionary writes, no DOM rebuild, no GSAP timeline restart, no appShell teardown.
- **L-2 — No layout shift beyond text-width change:** element boxes keep their constraints; only
  intrinsic text widths change (within the E-1…E-5 budgets).
- **L-3 — Intro overlay is exempt:** the intro is one-shot and BM-default from boot; live
  language re-render during the letter animation is explicitly out of scope (ARCHITECTURE
  decision). The overlay consumes `t()` at build time only.
- **L-4 — `document.documentElement.lang` swaps with the active language** (`"ms"` for BM —
  D-06); title and meta swap through the same `applyStaticHead`/`data-i18n` path as boot.
