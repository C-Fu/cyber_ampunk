# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (binds every section below):** The Phase 1 UI-SPEC (`.planning/phases/01-i18n-foundation/01-UI-SPEC.md`, status: **approved**) is the preserved visual identity — this phase does **not** reopen it. Type scale, color tokens, spacing, chrome geometry, and copy rules C-1…C-4 / T-1…T-4 / E-1…E-5 carry forward verbatim. This contract covers only the four NEW design surfaces Phase 2 introduces:

1. The **"BM | EN" toggle pill** — header button row (desktop) + Tetapan panel language row (D-08).
2. The **language hint toast** — dismissible, post-ENTER, one-tap switch (D-09).
3. **Language-swap visual behavior** — the contract for what the instant re-render looks like (D-02/D-04; L-1…L-4 from Phase 1, now exercised live).
4. **Intro story typographic presentation** — the 5–7 sentence KL rewrite (D-10) inside the existing `.intro-stack` layout, plus the `intro.*` copy contract.

Where this spec restates a locked decision from `02-CONTEXT.md` (D-01…D-10 LOCKED), the source is cited and the decision is NOT reopened. Autonomous run: agent-decided items are marked **[agent-decided]**.

### Intro story contract (INTRO-01/INTRO-02, D-06/D-10)

- **ST-1 — Arc (D-10, locked):** medium, 5–7 sentences — the KL runner, one delivery, a moment of tension in the monsoon rain, arrival. Flavor: neon-soaked Kuala Lumpur, Malaysian street texture (mamak, monsoon, motorbike courier), corporations looming in the background.
- **ST-2 — Native in both languages (D-10):** BM is a rewrite (not a translation of the old tagline); EN is a faithful counterpart of the BM (not literal). Cyberpunk register is ALLOWED here — this is the one surface where C-1's formal-clean rule relaxes per Phase 1 C-1 ("cyberpunk flavor reserved for the intro story").
- **ST-3 — Key shape (D-06, locked):** story text lives as `intro.*` dictionary keys — the single source of truth shared with Phase 3 TTS. **[agent-decided]** Structure: one key per sentence (`intro.story.s1`…`intro.story.s7`) rather than one blob key, because (a) Phase 3 TTS-02 needs sentence-sized utterances from the same source, (b) Phase 3 TTS-05 highlights the currently-spoken sentence — per-sentence keys make both mechanical. The overlay joins sentences with a space into one flowing paragraph (S-2). Sentence count fixed at 6 for the draft (mid-arc); owner may trim to 5 or extend to 7 in review.
- **ST-4 — Length budget (extends C-4):** total story ≤ **~460 chars BM / ~420 chars EN** (6 sentences × ~70–75 chars average). This is the budget that keeps the story within the layout limits derived in S-1. Per-sentence ≤ ~110 chars (TTS-02's ≤ 300-char ceiling has huge headroom, but overlay layout does not).
- **ST-5 — Drafts (owner reviews, D-07):** AI drafts the story in the dictionary files at implementation time and the plan schedules an owner-review checkpoint (mirroring Phase 1 01-04 D-10 review). This spec fixes structure, length, tone, and key layout — not the final prose.

### Toast copy contract (D-09)

- **TO-1 — Hint is in the CURRENT language, offering the OTHER one.** BM mode (first-visit default) → BM copy suggesting EN; the mirror applies if the user somehow landed EN-first. One line, ≤ ~40 chars BM (C-4 family), no body text, one action.
- **TO-2 — The action label names the target language explicitly** (`Tukar ke BM` / `Switch to English`) — never a bare "OK"/"Tukar".

## Component Contracts (the four new surfaces)

### TG — Toggle pill (header) + language row (settings) — D-08

- **TG-1 — Placement, header:** inside `.app-header-actions`, ordered FIRST (leftmost, before ABOUT) **[agent-decided]** — language is a global, mode-level control; it reads before the content links. Below 640px the ABOUT/SOURCE labels collapse to icons; **the toggle keeps its `BM | EN` text at all breakpoints** (2-char labels fit the 40px mobile row; nothing about it collapses) **[agent-decided]**.
- **TG-2 — Markup shape:** a single `<button>` with two inner spans (`.lang-toggle-segment`) — `<span class="lang-toggle-segment" data-lang="bm">BM</span><span class="lang-toggle-segment" data-lang="en">EN</span>`. One button = one focus stop = one `aria-pressed`-style state; two separate buttons would create a two-stop tab order for one setting. **[agent-decided]** The button carries `aria-label` (TG copy table) describing the CURRENT language and the switch action; segments are `aria-hidden` decoration for the sighted layout.
- **TG-3 — Visual states:** idle = `.app-header-about-btn` chrome (`var(--cyber-bg)`, `var(--cyber-border)`, `clip-path: var(--cyber-clip-sm)`, `box-shadow: var(--cyber-glow)`, 0.35s transitions). Active segment = accent treatment (Color section). Hover = the standard hover trio (`--cyber-bg-hover`, `--cyber-border-hover`, `--cyber-glow-hover`). A `2px` divider between segments at `var(--cyber-border)` opacity. NO third "hover-to-preview" state, NO animation between languages — the switch is instant per D-02.
- **TG-4 — Keyboard focus:** `:focus-visible { outline: 2px solid rgba(255, 255, 255, 0.35); outline-offset: 2px }` — copied verbatim from `.settings-toggle-input:focus-visible + .settings-toggle` so keyboard focus looks identical across the app. Enter/Space activate (native button). **[agent-decided]**
- **TG-5 — Interaction:** click anywhere on the pill toggles to the OTHER language (it is a 2-state control, not a segmented tab bar — no pointer-targeting of halves). `Enter`/`Space` = click. Calls `setLanguage(next)`; the header pill's own `syncText` subscription updates its active segment + aria on notify. **[agent-decided]**
- **TG-6 — Reversibility:** no confirmation, no toast on manual toggle — the toggle itself is the undo (and the persistent localStorage write, D-03, is the durable record).
- **TG-7 — Settings row (SR):** in the Tetapan panel, the language control is a row in the existing rhythm — **[agent-decided]** SR-1: a `.settings-section` with title (`Bahasa` / `Language`, cyan section-title style) containing a **single row of two segment buttons** side by side (`grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 10px` — the `.settings-look-grid` pattern), each segment a `.settings-look-btn`-shaped button with `aria-pressed` true/false. This reuses the panel's own two-state button language (look preset buttons) instead of importing the header pill's single-button form. No `aria-label` duplication: the section title + `aria-pressed` is the accessible contract.
- **TG-8 — Both controls, one store:** header pill and settings row call the same `setLanguage`; each subscribes via the standard factory `syncText()` so both stay in sync on any change (including the toast's one-tap switch — a third caller). State lives only in `i18n`; no component-local mirrors.
- **TG-9 — Chrome preservation:** the pill is inserted without touching `.app-header-brand` (HUD slot), existing buttons, or the 640px collapse behavior. `revealAppUi` gating (`app-header--force-hidden`) applies to the pill automatically as a child of the header — no extra show/hide wiring.

### TO — Language hint toast (D-09)

- **TO-3 — Trigger conditions (D-09, locked):** shown once after ENTER completes the intro (after `revealAppUi`), when `navigator.languages` contains neither `ms` nor `id` AND no stored language exists (first visit) AND the dismissal flag is not set. If the user stored a language, never show (their choice is made). If `navigator.languages` is empty/unavailable, treat as non-matching (show) — the dismiss flag still guards repeats.
- **TO-4 — Dismissal persistence:** a new `threejs-punk-lang-hint-dismissed` localStorage key via `userPreferences.js` (same try/catch pattern). Dismissing (X or acting) persists; reset configs does NOT clear it (it is a hint, not a config) **[agent-decided]**.
- **TO-5 — Position and chrome:** fixed, horizontally centered, `bottom: clamp(1.5rem, 5vh, 3rem)` (+ safe-area), `z-index: 1000` (header layer — it is chrome, not overlay content). Pill silhouette borrowed from `.performance-notice`: `border-radius: 999px`, `border: 1px solid rgba(255, 255, 255, 0.16)`, `background: rgba(8, 10, 14, 0.78)`, `backdrop-filter: blur(12px)`, Orbitron per `global.css` chrome font-family inheritance. Unlike the performance notice it is `pointer-events: all` (it has buttons). **[agent-decided]**
- **TO-6 — Contents and layout:** one flex row, `gap: 12px`, vertically centered: message `<p>` (single line, copy TO-1), one action `<button>` (text-only, cyan `var(--cyber-text)`, uppercase small label per the 9px/0.22em chrome label style, `background: transparent; border: 0; cursor: pointer`), one dismiss `<button>` (a Phosphor **X** at 16px — the ONLY icon in this phase, reused from `phosphorX` already imported in the codebase — with `aria-label` dismiss; 24px minimum hit area via padding). Max width `min(92vw, 30rem)`; if the message + action would exceed it, the action wraps below (flex-wrap) — never truncates the message. **[agent-decided]**
- **TO-7 — Motion:** in/out per the `.performance-notice` pattern: enter = `opacity 0→1` + `translateY(0.5rem → 0)`, 320ms ease; auto-dismiss after **10 s** (long enough to read one line, short enough to not squat over the walk hints) **[agent-decided]**; exit = reverse, then `root.remove()`. `prefers-reduced-motion: reduce` → opacity-only, no translate, 0ms. Hover/focus within the toast pauses the auto-dismiss timer. **[agent-decided]**
- **TO-8 — One-tap switch:** the action button calls `setLanguage(other)` — the standard notify loop re-renders all chrome; the toast itself immediately exits (its job is done) and the dismissal flag is set. The toast's own text does NOT live-re-render (it is about to be removed; re-rendering a hint into the language you just declined is noise). **[agent-decided]**
- **TO-9 — Keyboard/focus:** the action and dismiss buttons are real buttons with the TG-4 focus-visible treatment; `Escape` while focus is inside the toast dismisses it. The toast does NOT steal focus on appear (it is passive; `aria-live="polite"` announces the message). **[agent-decided]**
- **TO-10 — Module placement:** new `createLanguageHintToast.js` under `src/ui/chrome/` (it is post-reveal chrome, not intro-scoped) with co-located CSS — created from `createIntroFlow`'s `onStart` completion (after `revealAppUi()`), wired where `revealAppUi` is defined in `main.js`/`createAppShell`. `createRenderLoop.js` is untouched. **[agent-decided, CONTEXT integration point]**

### LS — Language-swap visual behavior (D-02/D-04, Phase 1 L-1…L-4 exercised live)

- **LS-1 — Instant, single frame:** a toggle performs only `textContent` / `setAttribute` writes through the existing notify loop (Phase 1 L-1; no `innerHTML` dictionary writes, no DOM rebuild, no appShell teardown). All subscribed `syncText()` functions run synchronously within one notify — the swap lands in one rendered frame, no intermediate mixed-language paint. **Verification:** a screenshot mid-swap shows either fully-BM or fully-EN chrome, never both.
- **LS-2 — No flash/reflow glitch:** element boxes keep their constraints (Phase 1 L-2); text-width changes stay within the E-1…E-5 budgets. The toggle pill's own width is constant (T-5). Header/settings/toast all re-render in the same frame — the checker sees zero perceptible layout jump beyond intrinsic text-width change.
- **LS-3 — Round-trip purity (D-04, locked):** BM→EN→BM leaves no English in BM mode and no BM in EN mode — including `document.title`, `<html lang>`, and all head metas through `applyStaticHead` (already swap-wired in `setLanguage`).
- **LS-4 — Fixed-chrome swap containment:** the only new fixed-width surface is the toggle pill (immune, T-5). The toast swaps only if visible across a manual toggle — its message re-renders via standard subscription **only while the toast is showing and was NOT auto-dismissed**; simplest compliant implementation: the toast subscribes like any chrome factory. **[agent-decided]**
- **LS-5 — Intro overlay exemption (D-05, locked):** the letter-split brand lines are NEVER re-synced (Phase 1 L-3 + D-05). The story/kicker/ENTER re-render safely — BUT see S-4: if the overlay is still on screen when the user toggles (possible once the header toggle exists — the header is hidden during intro, but the settings panel is reachable post-reveal only, so in practice the overlay swap path is: story text lives in a NON-letter-split `<p>`, re-rendered as plain `textContent`). The plan must flag this exact approach per D-05. **[agent-decided: story region is a plain paragraph, never letter-split — letter-split stays exclusive to the brand lines]**

### S — Intro story presentation (D-10, the layout-fit answer)

- **S-1 — Does 5–7 sentences fit the intro layout?** YES, with a measured budget — this is the phase's one real layout risk, resolved by geometry from `introOverlay.css` (read, not guessed):
  - `.intro-container` is `position: fixed; inset: 0; display: flex; align-items: center` with `padding: clamp(1.25rem, 4vw, 3rem)`.
  - `.intro-stack` is a centered column, `width: min(100%, 38rem)`, containing (in order): kicker, brand (2 lines, `clamp(2.6rem, 11vw, 5.75rem)` each, ~0.86 line-height), rule, **story paragraph**, ENTER button, credit.
  - The story region gets a **`max-height` constraint, not a scroll and not a line-clamp**: `max-height: 26.5rem` (≈ 12 lines of the 1.35 line-height ramp at the 1.35rem clamp ceiling; at 480px the 16.5rem max-width forces ~6 extra wrapped lines vs desktop — the budget below already accounts for both). **[agent-decided]**
  - **Budget math (binding, extends ST-4):** at desktop `max-width: 22rem` ≈ 34–38 chars/line of the tagline ramp → 460 chars BM ≈ 12–13 lines ≈ 11.5rem block height; plus brand ~8rem, kicker/rule/buttons/credit ~9rem, gaps ~4rem → total ≈ 33rem against a 1080p viewport's ~60rem available — comfortable. At 360px width (16.5rem max-width, ~26 chars/line): 460 chars ≈ 18 lines ≈ 16rem; brand shrinks to `clamp(2.35rem, 14vw, 3.4rem)` (~5rem) — total ≈ 35rem against a 640–700px (≈ 40rem) viewport: fits with ~5rem headroom. **The ST-4 budget (≤ ~460 chars BM) is the contract that makes 6 sentences fit at 360px without scroll.**
  - **Overflow behavior (edge case, must be defined):** if the owner's final prose exceeds the budget, the story region does NOT scroll and does NOT line-clamp — the copy is shortened to fit (ST-4 is a copy budget like Phase 1 E-2: shorten the copy first, never add a scroll region to a one-shot cinematic overlay). `overflow: hidden` on the region is the safety net so a review miss clips the tail of the last sentence instead of pushing the ENTER button off-screen. **[agent-decided]**
- **S-2 — Story region shape:** the existing `.intro-tagline` `<p>` BECOMES the story paragraph (same element role: the tagline is not kept alongside the story — the story replaces the one-liner per the phase goal). It keeps: `max-width: 22rem` (16.5rem ≤480px), the type ramp (T-6), `color: rgba(255, 255, 255, 0.9)`, text-shadow. It gains: `white-space: normal` (already default — sentences wrap as one flowing paragraph, joined with spaces, no `<br>` between sentences), and per S-1 the `max-height` + `overflow: hidden` guard. No new CSS class hierarchy — reuse `.intro-tagline` or add one modifier `.intro-tagline--story` scoped to the max-height/overflow additions only. **[agent-decided]**
- **S-3 — Animation:** the existing GSAP enter timeline animates the tagline element as one block (`opacity 0→1, y 14→0, 0.75s power2.out`) — the story rides the SAME tween (no per-sentence stagger this phase; per-sentence choreography belongs to Phase 3's TTS-05 highlighting, which will need a per-sentence span structure that this phase's `intro.story.s*` keys already enable). **[agent-decided — minimal diff, no timeline changes]**
- **S-4 — Swap behavior on the story (D-05):** the story `<p>` is plain text, not letter-split — `splitIntoLetters` remains exclusive to `.intro-brand-line`. If `setLanguage` fires while the overlay is visible, the story re-renders as `textContent` (LS-5). The story paragraph participates in the overlay's creation-time `t()` and in a small overlay `syncText()` covering kicker/story/ENTER (the Phase 1 01-02 SUMMARY already documented this exact constraint). The letter-split brand lines and the credit are excluded from `syncText` — `aria-label` on the brand (`THREEJS-PUNK`) is a fixed brand token, NOT translated, in either language. **[agent-decided, per D-05]**
- **S-5 — ENTER button:** unchanged (Phase 1: `MASUK`/`ENTER`, `min-width: 9.5rem`, one word, no wrap — E-3).
